# Dental Signal — iOS App Store Setup Guide
(Windows-friendly: no Mac or Xcode needed locally)

---

## Overview

You have:
- A Capacitor 5 project that wraps your Dental Signal web app
- Codemagic.io will build the iOS IPA on Mac servers (free tier available)
- Apple will distribute it via the App Store

---

## Step 1 — Create a GitHub repository

1. Go to github.com and create a **new private repository** called `dental-signal-ios`
2. Upload all files in this folder (dental-signal-ios-app) to the root of that repo
   - The structure should look like:
     ```
     package.json
     capacitor.config.json
     codemagic.yaml
     www/
       index.html
     ```
3. Push to GitHub

---

## Step 2 — Create your App Store listing

1. Go to appstoreconnect.apple.com and sign in with your Apple ID
2. Click **My Apps → +** to create a new app
3. Fill in:
   - **Platform:** iOS
   - **Name:** Dental Signal
   - **Primary Language:** English
   - **Bundle ID:** `com.dentalsignal.app` (you'll register this in step 3)
   - **SKU:** dental-signal-001
4. Save and note your **App Store App ID** (a number like 1234567890)
5. Edit `codemagic.yaml` and replace `YOUR_APP_STORE_ID` with that number

---

## Step 3 — Register your Bundle ID

1. Go to developer.apple.com → Certificates, Identifiers & Profiles → Identifiers
2. Click **+** → **App IDs** → **App**
3. Set:
   - **Description:** Dental Signal
   - **Bundle ID:** `com.dentalsignal.app` (Explicit)
   - **Capabilities:** Check **Push Notifications**
4. Register it

---

## Step 4 — Create an App Store Connect API Key

Codemagic needs this to upload your builds automatically.

1. appstoreconnect.apple.com → Users and Access → **Keys** tab
2. Click **+** and give it a name like "Codemagic Build"
3. Role: **App Manager**
4. Download the `.p8` key file (you only get one chance!)
5. Note the **Key ID** and **Issuer ID** shown on that page

---

## Step 5 — Set up Codemagic

1. Go to codemagic.io and sign in with GitHub
2. Click **Add application** → select your `dental-signal-ios` repo
3. Choose **React Native / Other** (the codemagic.yaml will handle everything)
4. Go to **Team settings → Integrations** and connect Apple Developer account:
   - Upload the `.p8` file you downloaded in Step 4
   - Enter the Key ID and Issuer ID
5. In your app settings → **Environment variables**, add:
   | Variable | Value |
   |---|---|
   | APP_STORE_CONNECT_PRIVATE_KEY | contents of your .p8 file |
   | APP_STORE_CONNECT_KEY_IDENTIFIER | your Key ID |
   | APP_STORE_CONNECT_ISSUER_ID | your Issuer ID |

---

## Step 6 — Add GoogleService-Info.plist for Push Notifications

For push notifications to work on iOS, you need a Firebase config file:

1. Go to console.firebase.google.com → your dental project → Settings (gear icon)
2. Scroll to **Your apps** → **iOS** → click **Add app**
3. Bundle ID: `com.dentalsignal.app`
4. Download **GoogleService-Info.plist**
5. Add it to your GitHub repo at: `ios/App/App/GoogleService-Info.plist`

Note: The `ios/` folder is generated by Codemagic during the build (`npx cap sync ios`).
You can add GoogleService-Info.plist as a Codemagic **File variable** instead:
- Variable name: `GOOGLE_SERVICE_INFO_PLIST`
- Upload the file
- Add this line to codemagic.yaml under scripts (before "Build iOS"):
  ```yaml
  - name: Add Firebase config
    script: |
      cp $GOOGLE_SERVICE_INFO_PLIST ios/App/App/GoogleService-Info.plist
  ```

---

## Step 7 — Trigger your first build

1. Go to your Codemagic app → click **Start new build**
2. Select branch: `main`
3. Select workflow: `dental-signal-ios`
4. Click **Start build**
5. Build takes ~15-20 minutes on Codemagic's Mac servers
6. If successful, the IPA is automatically submitted to TestFlight

---

## Step 8 — Test on your iPhone via TestFlight

1. On your iPhone, download **TestFlight** from the App Store
2. appstoreconnect.apple.com → your app → TestFlight tab
3. Add yourself as an internal tester
4. You'll get an email — tap it on your iPhone to install

---

## Step 9 — Submit for App Store Review

When you're happy with the app:

1. In `codemagic.yaml`, change `submit_to_app_store: false` to `submit_to_app_store: true`
2. Push to GitHub to trigger a new build
3. In App Store Connect, go to your app → Prepare for Submission
4. Fill in:
   - Screenshots (at least 6.5" iPhone screenshots — use your iPhone with TestFlight)
   - Description: "Dental Signal is a real-time paging system for dental offices. Staff tap to send instant signals to all connected devices simultaneously."
   - Keywords: dental, pager, signal, office, staff, communication
   - Age rating: 4+
   - Privacy Policy URL: you need one (can be a simple page on your Netlify site)
5. Submit for review (usually 1-3 days)

## Important Notes

### Subscription Compliance (App Store Rule 3.1.1)
The iOS app does NOT have in-app purchase for subscriptions — instead the paywall says
"Manage your plan at our website." This is fully App Store compliant because:
- You're directing users to a website to purchase (allowed for B2B/service tools)
- You are NOT charging in the app itself
- Apple only requires IAP if you're selling digital content/services *within* the iOS app

### Push Notifications
- Signals from Firebase trigger push notifications via Firebase Cloud Messaging
- Users must enable notifications when prompted (shown after first login)
- Notifications work even when the app is backgrounded or closed

### Subscription Status
- The app reads subscription status from Firebase Firestore
- Users who subscribe on the web version automatically get Pro in the iOS app
- Device limit enforcement is the same as the web version

## Troubleshooting

**Build fails: "No signing certificate"**
→ Make sure you connected your Apple Developer account in Codemagic Team Settings

**Push notifications not working**
→ Make sure you added GoogleService-Info.plist (Step 6) and Bundle ID has Push Notifications capability

**App crashes on launch**
→ Check Codemagic build logs — usually a missing npm package or capacitor sync error

**Firebase connection fails**
→ Make sure your Firebase project has iOS whitelisted in Authentication → Settings → Authorized domains
